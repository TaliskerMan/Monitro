# Monitro

**Monitro** is a cross-platform local system observability platform — inspired by [Monitorix](https://www.monitorix.org), built from the ground up with modern technologies. It is proudly part of the **Nordheim Online** portfolio of applications.

| Layer | Technology |
|---|---|
| UI | Flutter (macOS · Linux · Windows desktop) |
| Backend Collector | Dart native daemon |
| Storage | MariaDB (local, versioned schema) |
| Transport | HTTPS — 4096-bit locally-signed RSA SSL |

## What It Monitors

- **CPU** — per-core utilization, user/sys/idle breakdown
- **Memory & Swap** — used / free / cached / buffers
- **Disk I/O** — read/write rates per device
- **Filesystem Usage** — used/available per mount
- **Network Traffic** — per-interface bytes/sec & packets/sec
- **Active Connections** — TCP/UDP state breakdown (netstat)
- **Port Activity** — top listening ports with connection counts
- **Process Monitor** — top CPU/memory consumers (real-time, sortable)
- **User Sessions** — logged-in users, session duration, source host
- **API / HTTP Request Rates** — which processes are making excessive outbound calls
- **Alert Log** — threshold breach events with timestamps

## 🚀 Installation & Setup Guide

Monitro is designed around two decoupled components: a background telemetry collector daemon and a frontend UI dashboard. Both must be running to display data.

### Option 1: Debian/Ubuntu Installation (.deb)
The easiest way to install Monitro on Debian-based systems is via our pre-packaged binaries.

1. **Install MariaDB**  
   Monitro requires MariaDB to store telemetry data.
   ```bash
   sudo apt update
   sudo apt install mariadb-server
   sudo systemctl enable --now mariadb
   ```
2. **Setup the Database Schema**  
   Log in to MySQL as root and initialize the schema:
   ```bash
   sudo mysql -u root < db/migrations/001_initial_schema.sql
   ```
3. **Download and Install Monitro**  
   Grab the latest `.deb` release from [GitHub Releases](https://github.com/TaliskerMan/Monitro/releases) and install it:
   ```bash
   sudo dpkg -i monitro_1.2.3_amd64.deb
   ```
   *(Note: The installer will automatically generate unique 4096-bit SSL certificates for securely connecting the GUI to the local daemon!)*

4. **Configure the Collector**  
   Edit your configuration to match the MariaDB credentials you just created:
   ```bash
   nano /opt/monitro/config/monitro.yaml
   ```

5. **Start the Background Collector**  
   The collector must be running in the background **before** opening the app:
   ```bash
   /opt/monitro/backend/monitro_collector --config /opt/monitro/config/monitro.yaml &
   ```

6. **Launch Monitro!**  
   You can now launch Monitro from your App Grid, or by running `monitro` in your terminal.

---

### Option 2: Build From Source (macOS / Dev)

```bash
# 1. Clone the repo
git clone git@github.com:TaliskerMan/Monitro.git
cd Monitro

# 2. Generate local SSL certificates
chmod +x certs/gen_certs.sh
./certs/gen_certs.sh

# 3. Build & run the backend collector
cd backend
dart pub get
dart compile exe bin/monitro_collector.dart -o bin/monitro_collector
./bin/monitro_collector --config ../config/monitro.yaml &

# 4. Run the Flutter UI
cd ..
flutter pub get
flutter run -d macos
```

## 🛠️ Troubleshooting

If the Monitro Dashboard is empty or showing errors, check these common issues:

**1. "Address already in use (errno = 98) on port 8443"**
- **Cause:** You attempted to start the `monitro_collector` but an orphaned "zombie" instance is already running silently in the background and holding the network port lock.
- **Fix:** Kill the old daemon process manually:
  ```bash
  killall -9 monitro_collector
  # Then try starting it again
  /opt/monitro/backend/monitro_collector --config /opt/monitro/config/monitro.yaml &
  ```

**2. "KEY_VALUES_MISMATCH" or "Permission Denied (errno = 13) on server.key"**
- **Cause:** The SSL certificates in `/opt/monitro/certs/` were generated by the `root`/`sudo` user, blocking the regular user from reading the private key to start the HTTPS API.
- **Fix:** Ensure you own the certificate repository:
  ```bash
  sudo chown -R $USER:$USER /opt/monitro/certs/
  ```

**3. The "Network Connections" Dashboard is Empty!**
- **Cause:** By default, Monitro aggregates all network traffic globally but won't render the charts until a specific interface is pinned.
- **Fix:** Click **Settings** in the left sidebar, locate the **Monitored Network Interface** dropdown, and change it from "All" to your active connection (e.g., `eth0`, `wlp6s0`, `enp5s0`). The charts will instantly populate.

**4. UI Opens But Says "Cannot connect to Monitro backend"**
- **Cause:** The Flutter App cannot speak to the MariaDB server entirely, or the collector isn't running at all.
- **Fix:** Double check that MariaDB is active (`systemctl status mariadb`), verify your username/password in `/opt/monitro/config/monitro.yaml`, and ensure the `monitro_collector` process isn't throwing errors in your terminal.
